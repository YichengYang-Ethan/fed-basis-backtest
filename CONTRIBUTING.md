# Contributing to the research

Changes should identify the economic question, information set, data vintage and primary statistic before evaluating results. Report failed signals, missing observations and unfavorable sensitivities as well as positive outcomes.

Run `make verify` for a public-data/code change. If modifying chart data or reports, regenerate and visually review the affected figures. Publication manifests must be regenerated after intentional content changes and reviewed before upload.

Do not commit raw feeds, databases, private ledgers, credentials, signed URLs or account records. Use the documented environment variables and separate private input directories. Do not make paid acquisition part of tests, imports or CI. Source access and cost approval are separate from code verification.

A new parameter choice tested against the current nine positions remains exploratory. Proposals should include a falsification condition and a plan for genuinely new chronological observations. Avoid describing a conditional two-state payoff or a model margin scenario as a universal arbitrage or a liquidation guarantee.
